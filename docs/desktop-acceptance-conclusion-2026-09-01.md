# Qwen-CUA + Treeland 桌面能力阶段验收结论

日期：2026-09-01

## 1. 验收结论

当前框架对**有人监督、低风险、动作边界明确、可恢复的日常桌面测试**有条件通过。

当前已经能够完成并验证鼠标精确移动、单击/双击、打开本地文件、页面滚动、安全快捷键、空白文档输入与清理，以及同一任务中的多轮观察和执行反馈。Flat 配置修正后，`ydotool` 的绝对坐标移动已在真实 Treeland 桌面达到目标 `(100,100)`，实际读回误差为 0。

重复性样本：固定的受约束鼠标移动任务已连续运行 10 次，10/10 成功；目标 `(600,316)` 的模型动作和实际光标均为 `(599,316)`，最大量化误差 1 像素，未出现跨窗口、解析或执行失败。其余 4 个重复任务尚未完成。

该结论不等于已经具备无人值守的通用桌面自动化能力。当前不接受以下用途：高风险操作、长流程自主任务、没有后置条件校验的无人监督执行，以及对多显示器和复杂遮挡场景作可靠性承诺。

| 使用范围 | 当前结论 |
| --- | --- |
| 有人监督的低风险桌面测试 | 有条件通过 |
| 单步或短流程的移动、点击、滚动、输入 | 基础能力通过，执行前仍需检查提案 |
| 5 个任务各连续 10 次的稳定性基准 | 尚未验收 |
| 无人值守的日常桌面自动化 | 不通过 |
| 保存、删除、提交、付款、授权等高风险操作 | 不允许自动执行 |

## 2. 当前方案的优点

1. **视觉推理和确定性计算分层。** Qwen-CUA 负责理解截图、判断下一步动作；Treeland tree 和本地融合层负责窗口范围、坐标转换、执行前校验，不要求模型独自承担全部定位责任。
2. **Qwen 仍处于动作决策链路。** 控制层可以约束目标和合法动作，但不会绕过 Qwen 直接生成并执行动作；模型返回的单步建议必须经过解析、融合和校验。
3. **预测与执行分离。** `qwen_cua_predict` 不产生桌面副作用，主控 AI 可以检查动作、目标窗口和坐标后，再决定是否调用 `qwen_cua_execute`。
4. **异常输出有明确边界。** 每轮只接受一个 `computer_use` 调用，异常长响应和多动作响应在形成可执行提案前被拒绝，已阻止曾出现的约 53k tokens、至少 80 个重复 `moveTo` 问题。
5. **坐标执行已经打通。** 截图坐标、融合坐标、执行参数和执行后光标均可被观察；修正 Treeland DConfig 用户作用域和 Flat profile 后，真实桌面精确移动回归通过。
6. **具备真实反馈闭环。** 执行结果会反馈给同一 Qwen session；同一 instruction 下已验证第二轮能够读取前一步结果并返回 `DONE`。
7. **部署链路较简单。** Qwen-CUA 后端已经内嵌到本项目，正常运行不需要额外启动 `~/gui-mcp/` 服务，也不需要在两个服务之间重复维护推理状态。
8. **OmniParser 仍可作为基线。** 旧实现保留但默认不启用，后续可以在相同测试环境中单独启用，进行可重复的 A/B 对比。

## 3. 已确认可以覆盖的能力

- 获取截图和 Treeland window tree，并形成包含窗口候选、桌面坐标和相对坐标的融合结果。
- 在单显示器、当前已验证的 `1920x1080` 桌面中进行精确鼠标移动。
- 验证截图边界：最后一个合法像素 `(1919,1079)` 可精确执行并由 Tree 归属到 `TopContainer`；屏幕外一像素 `(1920,1080)` 在模型调用前被控制层拒绝。
- 在可恢复测试环境中执行单击、双击、滚动、按键、组合键和文本输入。
- 打开桌面本地 HTML 文件，并根据下一帧截图和活动窗口标题确认打开结果。
- 在空白、未保存的编辑器文档中输入固定文本，并清理到空文档状态。
- 阻止 pending 提案被同一 session 重复预测覆盖。
- 拒绝多动作或异常长的模型响应，避免批量误操作。
- 对同一 instruction 维持多轮模型历史，并提交实际执行反馈。
- 在同一窗口被平移后，按窗口内相对坐标重投影；已在真实桌面将 Text Editor 从 `(80,80)` 移至 `(280,96)` 后验证，冻结的相对点 `(320,220)` 被执行为 `(600,316)`，光标读回误差为 0。
- 在目标窗口变更时拒绝执行；已验证 Text Editor 的冻结提案被 Firefox 覆盖后返回 `target_window_changed`，且未注入鼠标动作。
- 目标窗口拒绝不会污染成功历史；真实回归中 Firefox 的冻结提案被 Text Editor 覆盖后得到 `rejected` 和 `history_turns=0`，同一 session 的下一轮可基于新截图提出新动作。

以上能力只在本轮记录的真实场景和单元回归范围内成立，不代表对所有应用和桌面布局的普遍保证。文本输入的“动作可执行、内容可见、可清理”已通过；字符级精确性尚未通过确定性读取验收：一次实际输入后，模型视觉转写将 `Qwen` 读成了 `Owen`，不能据模型自身描述证明文本逐字符正确。

2026-09-01 的修复后回归还确认：先执行带精确坐标约束的 `(100,100)` 移动，再以相同任务取消约束预测，真实 `qwen3_rl` 保留 `history_turns=1` 并返回 `DONE`，没有重复移动。动态控制提示不会再被误判为任务变更。

## 4. 当前确定无法覆盖或不能承诺的范围

### 4.1 当前实现明确缺失

- **不能可靠验证所有桌面子控件的语义。** Treeland tree 在已测桌面场景中只能提供 `BackgroundContainer` 等窗口级信息，不能区分桌面图标、Dock 子项和某些弹出层的具体归属；右击测试已经成功打开菜单，但当前无法仅凭 Tree 证明该菜单属于桌面文件还是 Dock。
- **不能用确定性规则证明任务已经完成。** 当前主要依赖下一帧和 Qwen 的主观判断；单次 `Ctrl+Z` 只删除一个字符时，Qwen 仍错误返回 `DONE`，说明执行成功不等于任务成功。
- **融合排除不可见窗口（2026-09-01 已修复）。** 根因是真实层名为 `WorkspaceContainer`/`BackgroundContainer` 而过滤只匹配小写 `workspace`；现改为大小写不敏感匹配，`visible=false` 的工作区窗口不再参与命中，并同步修正 `desktop_bounds_from_treeland` 的 `background` 层名匹配。真实复验：显示桌面后点击桌面背景，融合目标为 `BackgroundContainer` 而非隐藏全屏 Firefox，`matching_window_count=1`。
- **不能直接切换任务 instruction 并保留同一任务历史。** 当前实现检测到用户任务本身变化时会主动 reset session；复杂任务必须保持完全相同的任务 instruction，或由控制层另行管理任务状态。仅本轮使用的坐标约束提示已与任务身份分离，不再导致历史丢失。
- **状态接口语义（2026-09-01 已修复）。** `qwen_cua_status` 现区分 `pending_sessions`（仅真正待执行）与 `known_sessions`（全部本地已知 session），语义不再混淆。
- **端到端延迟不可预测（2026-09-01 已加计时工具，初步归因）。** 模型 telemetry 多为约 0.9～2.2 秒，但旧挂载 MCP 外层调用曾观察到约 55～215 秒等待。已为 predict/execute 加入 `stage_timings_ms` 分阶段计时（提交 `5d393d0`）。直连 127.0.0.1 采样：predict 总计 2.03s（模型 1.76s、截图+取树 0.27s）、外层调用 2.46s；execute 总计 0.48s——服务端与传输均无 55～215s 抖动，旧挂载链路/代理侧才是抖动源（待旧挂载复测确认）；`frame_capture_ms` 中取树约 0.27s 为后续优化点。
- **边界鼠标位置（2026-09-01 已修复）。** 执行前显式检测角落并返回结构化 `cursor_in_failsafe_corner`，不全局关闭 fail-safe；真实复验中光标位于 `(1919,1079)` 时 `Super+D` 被结构化拒绝且未注入按键，无原始 `FailSafeException`。
- **文本编辑语义不稳定。** `pyautogui.write` 逐字符输入可能使编辑器把单次撤销解释为只撤销一个字符，不能假设一次 `Ctrl+Z` 会撤销整段输入。
- **模型快捷键知识不能直接信任。** Qwen 曾把 Firefox 中的 `Alt+D` 当作显示桌面；只有明确约束为 `Super+D` 后才返回正确动作。

### 4.2 尚未完成验证，因此当前不能承诺

- 多显示器、负坐标、混合缩放、跨屏窗口和显示器动态插拔。
- 窗口移动后的坐标重投影、提案过期、目标窗口消失、遮挡变化和执行异常恢复的完整矩阵。
- 长流程任务、跨应用任务，以及连续运行后模型状态和本地状态的一致性。
- 5 个可重复桌面任务的重复验证：仅 1/5 鼠标移动已完成 10/10；3/5、4/5、5/5 尚无严格 10 连跑。输入任务的旧记录同时出现 9/10、8/10、17/18 与 16/18 等互相矛盾的汇总，必须回查原始证据后重跑或更正；在此之前不计入验收。
- 在全新安装环境中只安装本项目后的完整启动能力。
- 与迁移前 `gui-mcp` 后端在 prompt、消息、图像和坐标解析上的固定夹具等价性。

### 4.3 安全边界

保存或覆盖文件、删除、发送消息、提交表单、支付、授权、安装软件、执行终端命令等动作当前不纳入自动验收。即使模型提案看起来合理，也必须由主控层拒绝或要求人工确认。

## 5. 后续 OmniParser 独立对比测试

Qwen-CUA 问题另见 `docs/model-training-observations.md`。当前确认的视觉训练候选是文字视觉转写；桌面图标/Dock 的问题目前属于 Tree 子控件语义可观测性边界，尚无独立模型失败样本。快捷键知识、工具调用格式和完成判断则属于非视觉行为问题。Treeland 融合、坐标校验和后置条件验证仍是独立的系统责任。

OmniParser 将作为旧接口和对比基线保留，默认不启用。后续测试时单独启用 OmniParser，不与 Qwen-CUA 在同一次运行中共同决定动作，避免无法判断结果来自哪一条感知链路。

对比组至少包括：

- A 组：Qwen-CUA 视觉建议 + Treeland tree 融合和控制层校验；
- B 组：OmniParser 元素识别 + Treeland tree 融合和相同控制层校验。

两组必须使用相同桌面尺寸、缩放、应用初始状态、任务描述和安全限制。每次运行前恢复桌面状态，并保存：

- 原始截图和 Treeland tree 摘要；
- Qwen 原始动作或 OmniParser 原始元素结果；
- 解析结果、融合窗口、候选窗口和最终坐标；
- 实际执行动作、执行后截图、光标和窗口状态；
- 失败类型、恢复步骤、模型耗时和端到端耗时。

统一评价指标为：

1. 任务成功率；
2. 第一步动作正确率；
3. 坐标误差和目标控件命中率；
4. 目标窗口归属正确率与跨窗口误操作次数；
5. 非法输出拒绝率、错误动作漏过率和高风险提案数；
6. 平均步骤数、恢复次数、模型耗时和端到端耗时；
7. 错误 `DONE` 次数以及后置条件验证成功率；
8. Tree 信息缺失时的退化程度；
9. 可用时记录 token 和计算资源开销。

先完成手工测试指南中的 5 个任务各 10 次，再根据失败分层增加桌面图标、Dock、弹窗、遮挡、窗口移动和混合缩放专项。重复测试完成前，不根据少量成功样本宣布 Qwen-CUA 或 OmniParser 为最终方案。

## 6. 下一阶段通过条件

只有同时满足以下条件，结论才可从“有人监督的低风险测试有条件通过”升级：

- 完成 5×10 重复任务并保留完整证据；
- 消除不可见窗口参与目标融合的问题；
- 为关键任务加入可机器验证的后置条件，不以模型 `DONE` 作为唯一依据；
- 定位并约束端到端延迟；
- 完成陈旧提案、窗口移动、遮挡和执行失败恢复测试；
- Qwen-CUA 与 OmniParser 使用统一指标完成独立对比。
