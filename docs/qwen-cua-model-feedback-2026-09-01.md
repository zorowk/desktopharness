# Qwen-CUA 本地 Wayland 实测问题反馈

日期：2026-09-01  
对象：Qwen-CUA 模型研发人员  
关联评测：[单轮基线评测](qwen-cua-baseline-evaluation-2026-09-01.md)、[手工测试指南](manual-test-guide.md)

## 1. 环境、范围与归因规则

- 桌面：Wayland / Treeland，1920 × 1080。
- 本地服务遥测模型标识：`qwen3_rl`。
- 架构：Qwen-CUA 从截图提出动作；MCP 负责坐标换算、窗口命中、陈旧提案校验、实际执行和执行后观察。
- 本地 `qwen3_rl` 的权重、system prompt、视觉历史拼接方式尚未与论文的完整公开 scaffold 一一比对。因此本文报告的是**本地实际部署行为**，不直接等同于论文模型本体。

论文描述的 Qwen-CUA 仅观察截图，通过鼠标和键盘操作；其 agent scaffold 每轮最多保留 20 张活跃截图，旧截图按块折叠，但旧动作和推理保留在上下文中。详见 [Qwen-CUA 论文第 2.1、2.2 节](https://arxiv.org/html/2608.02352v1)。

本文按以下规则归因：

1. **模型问题**：在预测阶段，Qwen 已输出错误理解、坐标、策略或完成判断。
2. **MCP 问题**：窗口树、坐标转换、执行、陈旧提案校验或后置观察错误。
3. **证据不足**：没有独立真值时，不把现象直接归为模型缺陷。

## 2. 有较强证据的模型问题

### 2.1 多轮状态跟踪与步骤规划不可靠

复现任务：

```text
在当前计算器中先清空已有输入，然后只用屏幕点击完成 7 + 5 并显示结果 12。
每一轮只返回一个下一步 GUI 动作；完成且显示为 12 时返回 DONE。
不要操作其他窗口，不要使用键盘输入。
```

复现 session：`qwen-eval-t07-001`。初始画面中计算器显示 `7`。

第 1 步，模型识别到已有 `7`，提出点击清空按钮：

```text
原始截图坐标：[437,463]
映射后动作：click(839,500)
```

该动作由 MCP 成功执行、反馈到同一 session，下一轮模型遥测为 `history_turns=1`；窗口身份和执行链路均正常。

第 2 步，模型输出出现内部矛盾：

```text
The calculator is now clear after the previous action.
The display shows "7" ... I'll now click the "+" button.
```

随后提出：

```text
原始截图坐标：[564,517]
映射后动作：click(1083,558)
```

该动作未执行，session 已 reset。

该样本至少说明：模型没有可靠地融合“上一步实际动作 / 当前截图 / 任务计划”。它一方面称上一轮已清空，另一方面称当前显示仍为 `7`，并在没有可靠状态校验的前提下直接推进到 `+`，使固定流程遗漏了重新输入 `7` 的步骤。

说明：由于清空后的应用内文字没有使用独立 OCR、剪贴板或可访问性接口读取，不能仅凭本样本断言“实际屏幕一定已清空”。但模型自身叙述中的状态矛盾及流程未完成是确定的，建议作为状态融合与策略规划的复现案例。

研发建议重点检查：

- 上一步实际执行结果是否正确写入模型历史；
- 动作后的最新截图是否真正进入视觉上下文，顺序是否正确；
- 模型是否过度相信历史动作文字，而没有以最新截图校验状态；
- 历史与当前画面冲突时，模型能否表达不确定性、复核或停止推进。

### 2.2 应用图标/目标语义辨别错误

实际任务：打开 Calculator。

模型声称目标为 Calculator，并提出低风险 Dock 点击。该动作执行后，窗口数增加，但实际打开的应用为 `deepin-music`，而不是 Calculator。

由于实际结果可由窗口 `appId` 独立验证，本样本可较有把握地归为模型的视觉语义理解或动作选择错误，而不是 MCP 的坐标执行问题。

建议增加：

- 固定 Dock 布局下的应用图标分类评测；
- 相邻图标、相似图标及不同缩放下的定位评测；
- 点击后由窗口标题/appId 反馈纠错的能力评测；
- 不确定目标时先悬停/观察，而非直接点击的策略训练。

### 2.3 视觉文字转写错误：`Qwen` 被读为 `Owen`

已有历史样本中，编辑器文本输入后的视觉读取将 `Qwen` 转写为 `Owen`。

这应作为 OCR/视觉文字识别的训练候选。提交训练结论前需要同时保存：

- 原始截图；
- 模型无关的文本真值，例如剪贴板、AT-SPI、文件内容或人工逐字符标注。

若只用模型自身的图像描述判断文本正确性，无法区分“实际写错”与“模型读错”。因此目前应表述为“有文字视觉转写错误样本”，而非已完成字符级错误率统计。

### 2.4 完成状态判断会过早结束

历史样本中，文本编辑器执行一次 `Ctrl+Z` 后，实际只删除一个字符，模型仍返回 `DONE`。

该行为表明模型将“已执行撤销动作”错误地视为“任务目标已完成”，没有可靠核验最终文本状态。

风险：

- GUI 自动验收可能将部分完成误判为成功；
- 若外层将 `DONE` 当作测试通过，会产生静默假阳性；
- 错误 `DONE` 会中断后续纠错。

建议将“动作执行成功”和“目标状态满足”拆开建模；在 `DONE` 前要求可见且可验证的最终状态。文本、数值、开关和保存状态应由外部确定性断言决定。

### 2.5 快捷键知识不稳定

历史样本中，模型将 Firefox 的 `Alt+D` 当作显示桌面；在当前桌面环境中，应明确约束为 `Super+D`。

该问题属于平台/应用快捷键知识与动作选择错误，不是坐标问题。建议按 Linux/Wayland/Deepin/Treeland、桌面与浏览器快捷键冲突等维度建立评测。

### 2.6 工具输出协议不稳定

历史上出现过：

- 单轮多动作；
- 异常长动作串；
- 一次约 53k tokens、至少 80 个重复 `moveTo` 的响应；
- 长文本 `write` 截断样本。

当前 MCP 会在形成可执行提案前限制或拒绝异常输出，因此未导致批量误操作；这表示系统兜底有效，**不代表模型的协议服从已经稳定**。

长文本截断的失败率在历史记录中不一致，需用固定文本长度、字符集、编辑器、采样参数与确定性文本读取重新统计，不能在复验前报告精确失败率。

## 3. 已观察到但尚不能定性的样本

### 3.1 桌面图标提案未验证，Tree 不能提供其控件语义

任务：打开新的空白文本编辑器，但不输入、不保存。

模型称桌面左侧存在文本编辑器图标，提出点击 `(136,273)`。当前 Treeland 窗口树将该点归为 `BackgroundContainer`，该动作随后被人工决定不执行。

这不能证明模型识别错误：桌面图标本来就属于背景层，而当前 Tree 不提供桌面图标或窗口内部控件的子控件语义。Tree 只能提供顶层窗口/容器的几何、可见性、层级、工作区和坐标命中关系。

正确的研发表述应为：

> 模型在文本编辑器启动任务中提出了一个桌面图标坐标。由于提案未执行，尚不知道它能否打开 Text Editor；由于 Tree 不提供图标语义，也不能依据 `BackgroundContainer` 将其定性为视觉幻觉或图标定位错误。

融合规则：Tree 可用于验证某个坐标是否仍命中同一顶层窗口、该窗口是否被遮挡、是否移动、是否可见；不得用于判断窗口内部按钮、文本、列表项、桌面图标或 Dock 图标是否存在、属于何种应用或是否为任务目标。这些控件级语义只能来自截图视觉、OCR、无障碍树、应用 API 或执行后的确定性结果。

## 4. 不应归咎于 Qwen-CUA 的结果

以下是 MCP 确定性控制层的通过案例，不能包装成模型能力提升：

1. 同一 session 存在 pending 提案时，第二次预测被拒绝。
2. 已生成指向 Calculator 的鼠标移动提案后，用 File Manager 覆盖该目标位置，执行返回：

```text
status=refused
reason=target_window_changed
backend_feedback.committed=false
```

没有注入鼠标动作。

这证明 Treeland/MCP 的 pending 与遮挡保护有效；Qwen 并没有在遮挡后自行重新观察并主动拒绝，因为该轮没有重新调用模型预测。

## 5. 面向研发的结论

Qwen-CUA 在“窗口明确、控件明显、单步、动作限制严格”的场景中可提出可用候选动作。例如当前计算器 `7` 键的单步定位与点击曾成功完成。

但本地实测显示，它不适合作为可靠的多步自主验收代理，主要风险为：

1. 当前截图状态与历史动作记忆融合不稳定；
2. 状态变化后会跳步推进；
3. 应用图标与 GUI 入口的语义识别需使用截图和执行结果独立验证；不能由 Tree 的背景/窗口容器分类推断；
4. `DONE` 不能作为任务完成的可信依据；
5. 工具输出协议存在历史失控样本。

用于“写完代码后的 GUI 自动验收”时，合理定位应是：

> Qwen-CUA 只负责受控执行预定义 GUI 步骤；测试是否通过必须由退出码、日志、DOM/API、剪贴板、AT-SPI、文件内容或其他确定性断言判定。不得仅以 Qwen 的自然语言观察或 `DONE` 判定通过。

## 6. 建议提供给研发的最小复现包

每个失败样本建议至少包含：

- 初始截图和每步动作后的截图；
- 完整 task prompt、system prompt、模型版本、采样参数；
- 每轮模型原始 reasoning/action；
- 完整视觉历史顺序及是否发生折叠；
- 上一步实际执行动作和执行结果在上下文中的注入位置；
- 原始坐标、坐标映射结果与实际执行坐标；
- 与模型无关的任务真值；
- 失败分类：视觉感知、视觉定位、状态跟踪、步骤规划、完成判断或协议输出。

最优先复现实验：固定计算器初始状态，逐步执行：

```text
清空 → 7 → + → 5 → = → 外部验证 12
```

逐步比对模型对当前屏幕的描述、模型历史和实际界面状态，可区分主要根因是视觉状态读取、历史拼接，还是策略规划。
