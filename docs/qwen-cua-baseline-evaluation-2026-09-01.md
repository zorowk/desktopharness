## 归因说明

本轮没有发现 MCP 坐标重投影、窗口融合、陈旧提案校验或执行器错误：实际光标与融合动作一致，目标窗口在动作前后均为同一 Calculator 窗口。T03 还确认了 pending 提案会被 MCP 拒绝，T06 确认目标被 File Manager 遮挡后会以 `target_window_changed` 拒绝且不提交动作。两项都是 MCP 的确定性安全兜底，不能记为 Qwen 的鲁棒性得分。T07 的错误发生在预测阶段，尚未执行，首要归因是 Qwen 的 `qwen_planning`，并有 `qwen_state` 的状态识别矛盾。T08 仅证明 Tree 将桌面图标坐标归为背景层；Tree 不具备图标语义，且提案未执行，不能归因给 Qwen 或 MCP。上述成功也不抵消历史上已记录的输出截断、多动作串、错误快捷键或错误完成判断样本。

## 结论

Qwen-CUA 在这次低风险、单步、目标固定的计算器微流程中可以胜任受控 GUI 操作；但它未完成同一环境中的固定多步流程，因而不能将其作为能可靠组织多步验收的执行者。T08 未验证，不能据此判断桌面图标理解能力。它仍不适合作为代码验收的唯一判断者：通过条件必须由测试退出码、DOM/API、日志、剪贴板、AT-SPI 或其他确定性断言给出。遮挡/平移、恢复和稳定性仍需单独测量。
